# Лабораторная работа №4: Добавление механизма Proof-of-Work в распределённый блокчейн

## Цель работы

Научиться реализовывать и интегрировать механизм консенсуса Proof-of-Work (PoW) 
в распределённую блокчейн-систему, понять, как PoW защищает сеть от спама и атак, 
обеспечивает честное добавление блоков и влияет на скорость формирования цепочки.

## Теоретическая основа

**Proof-of-Work (PoW)** — это алгоритм консенсуса, при котором узел должен выполнить 
вычислительно сложную, но легко проверяемую задачу, чтобы добавить новый блок в цепочку.

В классическом виде задача формулируется так: найти такое значение `nonce`, при котором 
хэш блока начинается с заданного количества нулей (например, 4 нуля в шестнадцатеричной 
записи → `0000...`).

Этот подход:
- замедляет создание блоков, делая атаки экономически невыгодными;
- обеспечивает, что только один узел (первый решивший задачу) может добавить блок;
- требует от всех узлов проверки корректности найденного nonce.

В отличие от простого правила «первый прислал — тот и прав», PoW делает невозможным 
мгновенное создание блока — требуются время и вычислительные ресурсы.


## Реализованные компоненты

### 1. Класс Block
- Поле `nonce` — целое число, выбираемое в процессе майнинга
- Метод `calculate_hash()` — вычисляет SHA-256 от `index + timestamp + data + previous_hash + str(nonce)`
- Метод `mine_block(difficulty)` — перебирает nonce до тех пор, пока хэш не начнёт 
  с заданного количества нулей

### 2. Класс Blockchain
- Поле `difficulty` (по умолчанию 4)
- Метод `add_block(data)` — создаёт блок, майнит его и добавляет в цепочку
- Метод `is_valid()` — проверяет целостность всей цепочки
- Метод `is_block_valid(block)` — проверяет отдельный блок, включая соответствие PoW

### 3. Класс Node
- Метод `create_and_broadcast_block(data)` — майнит блок локально, затем рассылает
- Метод `receive_block(block)` — проверяет PoW и корректность блока перед добавлением
- Метод `broadcast_block(block)` — ретранслирует блок всем соседям
